# 第一章：温故而知新

## 1.1 从 Hello World 说起

### 程序从源代码到可执行文件的完整过程

让我们通过一个简单的 Hello World 程序来了解整个编译过程：

```c:source/_posts/程序员自我修养/code/hello_world.c
#include <stdio.h>

int main() {
    printf("Hello, World!\n");
    return 0;
}
```

#### 1. 预处理（Preprocessing）

预处理阶段主要处理以下内容：
- 处理所有的预处理指令（以 # 开头的指令）
- 展开所有的宏定义
- 处理条件编译指令
- 删除注释

可以使用以下命令查看预处理后的文件：
```bash
gcc -E hello_world.c -o hello_world.i
```

#### 2. 编译（Compilation）

编译阶段将预处理后的文件转换为汇编代码：
```bash
gcc -S hello_world.i -o hello_world.s
```

生成的汇编代码大致如下：
```assembly
    .section    __TEXT,__text,regular,pure_instructions
    .build_version macos, 10, 15    sdk_version 10, 15
    .globl  _main                   ## -- Begin function main
    .p2align    4, 0x90
_main:                                  ## @main
    pushq   %rbp
    movq    %rsp, %rbp
    subq    $16, %rsp
    leaq    L_.str(%rip), %rdi
    movb    $0, %al
    callq   _printf
    xorl    %ecx, %ecx
    movl    %eax, -4(%rbp)
    movl    %ecx, %eax
    addq    $16, %rsp
    popq    %rbp
    retq
```

#### 3. 汇编（Assembly）

汇编阶段将汇编代码转换为机器码：
```bash
gcc -c hello_world.s -o hello_world.o
```

#### 4. 链接（Linking）

链接阶段将目标文件与所需的库文件链接，生成可执行文件：
```bash
gcc hello_world.o -o hello_world
```

### 编译、链接、装载的基本概念

#### 编译
编译是将高级语言转换为汇编语言的过程，主要包括：
- 词法分析：将源代码分解成标记（token）
- 语法分析：将标记组织成语法树
- 语义分析：检查语法树的语义正确性
- 中间代码生成：生成中间表示
- 目标代码生成：生成汇编代码

#### 链接
链接是将多个目标文件合并成一个可执行文件的过程，主要包括：
- 地址和空间分配
- 符号决议
- 重定位

#### 装载
装载是将可执行文件加载到内存中运行的过程，主要包括：
- 创建进程
- 分配虚拟地址空间
- 加载可执行文件
- 设置程序入口点

## 实践练习

1. 编译过程实验
```bash
# 1. 预处理
gcc -E hello_world.c -o hello_world.i

# 3. 汇编
gcc -c hello_world.s -o hello_world.o

# 4. 链接
gcc hello_world.o -o hello_world

./hello_world
```

```bash
# 查看文件大小
ls -l hello_world

# 查看文件依赖
ldd hello_world
```

## 对比分析

本章作为全书的开篇，从 Hello World 出发，勾勒了"源代码 → 预处理 → 编译 → 汇编 → 链接 → 装载 → 运行"的全景。本节将这一全景与后续各章、与其他编译链接工具链进行对比，帮助读者建立清晰的认知坐标。

### 1. 编译链接全流程四阶段横向对比

| 阶段 | 输入 | 输出 | 关键工具 | 后续章节深入 | GCC 对应选项 |
|:--|:--|:--|:--|:--|:--|
| 预处理 | .c / .h | .i 展开文本 | cpp | 第二章 2.1 | `gcc -E` |
| 编译 | .i | .s 汇编 | cc1（GCC）/ clang 前端 | 第二章 2.2 | `gcc -S` |
| 汇编 | .s | .o 目标文件 | as（GNU Binutils） | 第三章 段/symbol | `gcc -c` |
| 链接 | .o / .a / .so | 可执行文件 | ld / ld.lld / mold | 第四、五章 | `gcc`（默认） |
| 装载 | ELF 可执行 | 进程 | 内核 execve + ld.so | 第六、七章 | — |

### 2. 主流构建工具链对比

| 工具链 | 前端 | 汇编器 | 链接器 | 优势 | 适用场景 |
|:--|:--|:--|:--|:--|:--|
| GCC | cc1 | gas | ld（GNU ld） | 生态最广、ABI 成熟 | 通用 Linux 开发 |
| LLVM/Clang | clang | llvm-mc | lld | 编译快、模块化、诊断友好 | 跨平台、CI、大项目 |
| MSVC | cl.exe | ml64 | link.exe | Windows 原生最佳 | Windows 平台 |
| 现代链接器 | — | — | mold / lld / wild | 比 GNU ld 快数倍 | 大型 C++ 项目 |

### 3. 优缺点

- 优点：分层模型让"问题定位"变得简单——链接错看 ld、装载错看 ld.so、段错看 as 输出。
- 缺点：教科书级分层在 LTO、PGO、JIT 等现代流程中界限模糊（例如 LLVM 的 LTO 把链接前移到编译期）。

### 4. 何时选

- 学习阶段：手敲 `gcc -E/-S/-c` 四步，把每一层都落到磁盘上观察，是建立直觉的最快方式。
- 工程项目：默认使用 `gcc` 或 `clang` 驱动，自动隐藏中间文件；大项目可考虑 `mold`/`lld` 加速链接。
