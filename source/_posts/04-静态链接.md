# 第四章：静态链接

## 4.1 空间与地址分配

### 空间分配

静态链接时，链接器需要为每个目标文件分配空间。主要包括：
1. 代码段空间
2. 数据段空间
3. BSS 段空间

示例代码：
```c:source/_posts/程序员自我修养/code/static_a.c
#include <stdio.h>

int a = 10;
int b = 20;

void func_a() {
    printf("a = %d, b = %d\n", a, b);
}
```

```c:source/_posts/程序员自我修养/code/static_b.c
#include <stdio.h>

int c = 30;
int d = 40;

void func_b() {
    printf("c = %d, d = %d\n", c, d);
}
```

```c:source/_posts/程序员自我修养/code/static_main.c
#include <stdio.h>

extern void func_a();
extern void func_b();

int main() {
    func_a();
    func_b();
    return 0;
}
```

编译和链接命令：
```bash
# 编译
gcc -c static_a.c -o static_a.o
gcc -c static_b.c -o static_b.o
gcc -c static_main.c -o static_main.o

# 链接
gcc static_a.o static_b.o static_main.o -o static_program

# 查看空间分配
objdump -h static_program
```

### 地址分配

链接器需要为每个符号分配地址。主要包括：
1. 代码段地址
2. 数据段地址
3. BSS 段地址

使用以下命令查看地址分配：
```bash
# 查看符号地址
nm static_program

# 查看详细的段信息
readelf -S static_program
```

### 符号解析

链接器需要解析所有符号的引用。主要包括：
1. 全局符号解析
2. 局部符号解析
3. 弱符号解析

示例代码：
```c:source/_posts/程序员自我修养/code/symbol_resolve_a.c
#include <stdio.h>

int global_var = 10;
static int static_var = 20;

void func_a() {
    printf("global_var = %d, static_var = %d\n", global_var, static_var);
}
```

```c:source/_posts/程序员自我修养/code/symbol_resolve_b.c
#include <stdio.h>

extern int global_var;
static int static_var = 30;

void func_b() {
    printf("global_var = %d, static_var = %d\n", global_var, static_var);
}
```

```c:source/_posts/程序员自我修养/code/symbol_resolve_main.c
#include <stdio.h>

extern void func_a();
extern void func_b();

int main() {
    func_a();
    func_b();
    return 0;
}
```

编译和链接命令：
```bash
# 编译
gcc -c symbol_resolve_a.c -o symbol_resolve_a.o
gcc -c symbol_resolve_b.c -o symbol_resolve_b.o
gcc -c symbol_resolve_main.c -o symbol_resolve_main.o

# 链接
gcc symbol_resolve_a.o symbol_resolve_b.o symbol_resolve_main.o -o symbol_resolve_program

# 查看符号解析结果
nm symbol_resolve_program
```

## 4.2 符号解析与重定位

### 符号解析

符号解析的过程：
1. 收集所有目标文件的符号
2. 建立符号表
3. 解析符号引用

示例代码：
```c:source/_posts/程序员自我修养/code/resolve_a.c
#include <stdio.h>

int a = 10;
void func_a() {
    printf("a = %d\n", a);
}
```

```c:source/_posts/程序员自我修养/code/resolve_b.c
#include <stdio.h>

extern int a;
void func_b() {
    printf("a = %d\n", a);
}
```

```c:source/_posts/程序员自我修养/code/resolve_main.c
#include <stdio.h>

extern void func_a();
extern void func_b();

int main() {
    func_a();
    func_b();
    return 0;
}
```

编译和链接命令：
```bash
# 编译
gcc -c resolve_a.c -o resolve_a.o
gcc -c resolve_b.c -o resolve_b.o
gcc -c resolve_main.c -o resolve_main.o

# 链接
gcc resolve_a.o resolve_b.o resolve_main.o -o resolve_program

# 查看符号解析结果
nm resolve_program
```

### 重定位

重定位的过程：
1. 计算符号的最终地址
2. 修改符号引用
3. 更新重定位表

示例代码：
```c:source/_posts/程序员自我修养/code/relocate_a.c
#include <stdio.h>

int a = 10;
void func_a() {
    printf("a = %d\n", a);

```

```c:source/_posts/程序员自我修养/code/relocate_b.c
#include <stdio.h>

extern int a;
void func_b() {
    printf("a = %d\n", a);
}
```

```c:source/_posts/程序员自我修养/code/relocate_main.c
#include <stdio.h>

extern void func_a();
extern void func_b();

int main() {
    func_a();
    func_b();
    return 0;
}
```

编译和链接命令：
```bash

gcc -c relocate_b.c -o relocate_b.o
gcc -c relocate_main.c -o relocate_main.o

# 链接
gcc relocate_a.o relocate_b.o relocate_main.o -o relocate_program

# 查看重定位信息
objdump -r relocate_a.o
objdump -r relocate_b.o
objdump -r relocate_main.o
```

### 重定位表

重定位表记录了需要重定位的位置。主要包括：
1. 重定位类型
2. 重定位符号
3. 重定位地址

使用以下命令查看重定位表：
```bash
# 查看重定位表
readelf -r relocate_program

# 查看详细的段信息
readelf -S relocate_program
```

## 对比分析

本章讲解静态链接器 ld 的三大任务：空间地址分配、符号解析、重定位。本节将其与动态链接、LLVM LTO、以及 GNU ld vs lld/mold 进行对比。

### 1. 静态链接 vs 动态链接

| 维度 | 静态链接（本章） | 动态链接（第五、七章） |
|:--|:--|:--|
| 链接时机 | 编译时一次性 | 装载时 + 运行时按需 |
| 输出 | 含代码副本的 ELF | 仅含 .so 路径的 ELF |
| 二进制体积 | 大 | 小 |
| 启动速度 | 快 | 略慢（需解析 .so） |
| 升级方式 | 重新编译 | 替换 .so 即可 |
| 内存占用 | 每进程一份 | 多进程共享只读段 |
| PIC 要求 | 不需要 | 必须 -fPIC |

### 2. 静态库（.a）vs 动态库（.so）本质

| 特性 | .a（ar 打包） | .so（共享对象） |
|:--|:--|:--|
| 链接器产物 | 拷贝到可执行文件 | 不拷贝，仅记录依赖 |
| 符号解析粒度 | 目标文件级 | 全局符号 |
| 更新生效 | 需重新链接 | 替换 .so 即生效 |
| ABI 兼容 | 编译期约定 | 需管理 soname/版本 |

### 3. GNU ld vs 现代链接器

| 链接器 | 速度 | 内存 | 特性 | 何时选 |
|:--|:--|:--|:--|:--|
| GNU ld（bfd） | 慢 | 大 | 老牌、文档全 | 通用默认 |
| GNU ld（gold，已弃维护） | 中 | 中 | 比 bfd 快 | 老项目 |
| lld（LLVM） | 快 | 中 | 跨平台、行为兼容 GNU ld | 跨平台/Clang 项目 |
| mold | 极快 | 低 | 单遍链接、C++ 友好 | 巨型 C++ 项目 |

### 4. 优缺点

- 优点：自包含部署，零运行时依赖，符号版本简单可控。
- 缺点：体积膨胀、补丁需全量重链、C++ 模板导致最终二进制巨大。

### 5. 何时选

- 嵌入式/容器单一可执行文件 → 静态链接。
- 桌面/服务端库频繁更新 → 动态链接。
- 大型 C++ 项目链接慢 → `mold` 或 `lld`。
